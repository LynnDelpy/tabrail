- (direction by user) the resizing is really clunky and breaks stuff
- (note) Repro (throwaway tmux 3.8, 3 tabs, 120 cols, sidebar 26/content 93): tmux spreads a window resize evenly over panes; 120->73 gave sidebar 2, 73->93 gave 12; never returns to 26
- (note) window-size latest resizes only shown windows; other tabs drift separately when visited (seen 21/26/12): sidebar jumps on tab switch
- (note) Stale rows: tmux reflows the grid on width change; draw::changes skips unchanged lines and blank rows never change, so row 1 kept '2 tmp' after a 42->26 drag
- (note) Border drag (default MouseDrag1Border resize-pane -M) changes that tab's sidebar only; tmux has MouseDragEnd1Border with no default binding
- (note) Not affected: closing a content split gives columns to the right neighbour; select-layout even-horizontal does equalise the sidebar (40 at 120 cols)
- (note) Harness pitfall: tmux -L outer without -f /dev/null loads ~/.tmux.conf, so the viewer runs its own tabrail sidebar plus resurrect/continuum
- (decision by user) Symptoms confirmed: tabs differ in width; stale text; also 'old tabs or duplications arise'
- (decision by user) Width rule: dragging the border sets one width for every tab; tmux resizes never change it
- (decision by user) Terminal too narrow for sidebar plus usable content: the sidebar hides, returns when wide again
- (decision by user) Mode express, slug sidebar-width; README.md and AGENTS.md adopted as companions; repro and causes in spec-authored brownfield.md
- (capability) CAP-1 one sidebar width shared by every tab; terminal resizes leave it, the content pane takes the whole change
- (capability) CAP-2 dragging a sidebar border sets the shared width; other tabs show it when visited, new tabs open at it
- (capability) CAP-3 after any sidebar size change the screen shows exactly the current rows: no fragments, no stale or duplicated tab rows
- (capability) CAP-4 terminal below a threshold: sidebar hides; wide enough again: back at the shared width with current rows
- (constraint) One width per tmux server, held in tmux (no file), so sidebars and tabrail-tmux ensure (WIDTH=26 today) agree; default 26, settable in tmux.conf
- (constraint) No process spawned per resize or tab switch (README: nothing spawned on tab switch); corrections via the control connection or hooks/bindings without run-shell
- (constraint) Draw-only-changed-lines and menu pause (AGENTS.md menu pitfalls) stay; a full repaint only when the size changes
- (constraint) A hidden sidebar is not re-added by tabrail-tmux ensure (client-attached, new tab) while the terminal stays narrow, and reap does not close its tab
- (constraint) README.md setup/behaviour and AGENTS.md option list gain the width option and drag rule
- (constraint) Verification only on throwaway servers; viewer started with -f /dev/null
- (assumption) 'old tabs or duplications' = stale or repeated tab rows inside the sidebar after a resize (reflow leftovers), not a second sidebar pane
- (assumption) Width option named @sidebar_width (global), default 26
- (assumption) Only a mouse drag of a sidebar border sets the width; keyboard resize-pane on a sidebar is undone like any other change
- (assumption) One width across all sessions of the server; a dragged width lasts until the server stops (resurrect does not save global options)
- (assumption) One frame at the wrong width right after switching to a tab tmux just resized is acceptable; the settled width is the contract
- (question) Hide threshold: terminal below N columns, or content pane below N (e.g. 80)?
- (question) tmux layout commands (prefix Space next-layout, select-layout) move or resize the sidebar: restore it left at the shared width, or out of scope?
- (note) Non-goals: per-tab or per-session widths, a hide/show toggle or right-side sidebar, row truncation rules (tab-rows), zoom (prefix z) behaviour
